# Handover — 2026-08-13

For Asi. Quick orientation to pick this up cold.

## What this is

`ilanel-poc` — a WordPress + WooCommerce proof-of-concept showing ILANEL's
catalogue and projects could look like [Ross Gardam](https://www.rossgardam.com.au/)
if moved off Squarespace. See the [README](../README.md) for the full pitch
and [ARCHITECTURE.md](ARCHITECTURE.md) for how it's built. This doc is just
"what's the state right now and what's next."

## Run it

One click, no install — boots WordPress + WooCommerce in-browser:

```
https://playground.wordpress.net/?blueprint-url=https://raw.githubusercontent.com/aninim/ilanel-poc/master/dist/blueprint.json
```

Nothing persists (it's a demo, not a host). See [INSTALL.md](INSTALL.md) for
a real local install (LocalWP) if you want state that sticks.

## Resolved today: missing gallery images on Projects / Light Art pages

Reported: project pages and Light Art pages render fine structurally, but not
every story row had a photo — some paragraphs showed text with a blank gap
where an image should sit.

**Root cause:** a data gap, not a template bug. Both
`themes/ilanel-poc/single-project.php` and `single-light_art.php` correctly
pair each content paragraph with one image from that item's `gallery` array.
But `data/projects.json` had 15 of 51 projects where `gallery` was shorter
than the paragraph count (mostly capped at exactly 3 images regardless of
paragraph count — 2 projects had zero gallery images at all), and
`data/light-art.json` had 2 of 13 works with the same gap. No script in
`scripts/` regenerates these two JSON files, so whatever produced them
originally capped the gallery short of what's on the live pages.

**Fixed:** re-checked all 17 affected items against their live pages
(`ilanel.com/projects/<slug>` and `ilanel.com/light-art/<slug>`) and
backfilled `gallery` with every real photo found that wasn't already stored.
10 of 15 projects and both Codex-verified projects gained their missing
images (12 projects total, some going from 3 → up to 10 images). **5 gaps
remain and are confirmed genuine** — those live pages really do have fewer
photos than text paragraphs, not a data error:

- `royal-bank-chambers-art-deco-chandelier` (3 images, 4 paragraphs)
- `wework-sydney-timeless-halo-lighting` (1 image, 2 paragraphs)
- `monolith-brass-pendant-light` (0 images, 2 paragraphs)
- `brassdrums` (0 images, 1 paragraph)
- `jcvagedcare` (2 images, 4 paragraphs)
- both Light Art gaps (`lightmatter-modern-designer-lighting-sculpture`,
  `tree-change`) — each live page only has 1 total photo, already used as
  hero, so no gallery image exists to backfill.

No template changes were needed — this was purely a `data/projects.json`
edit.
